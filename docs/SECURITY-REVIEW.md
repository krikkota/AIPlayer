# Проверка безопасности AIPlayer 0.2.0

Дата: 16 ноября 2026. Область: исходный код плеера, Qt/QML-интерфейс, загрузка и запуск ASR, локальный API Ollama, кэш и экспорт, зависимости установленного окружения и подготовка сборки для трёх ОС.

Дополнение 17 ноября: Windows-установщик уже собран нативно в закрытом GitHub Actions и скачан с проверкой SHA-256/PE x64. Функциональное тестирование Windows и пробная установка по просьбе пользователя не проводились. Результат — WINDOWS-INSTALLER.md; упоминания неподготовленной Windows-сборки ниже отражают состояние на момент исходного аудита 16 ноября.

Дополнение 17 ноября, 0.2.1: ошибка старта 0.2.0 воспроизведена и исправлена; новый установщик прошёл настоящую установку и запуск первого окна на Windows Server 2022. Подробности и ограничения проверки: WINDOWS-INSTALLER.md.

## Что защищаем и где граница

Защищаем исходные записи от перезаписи, приложение от некорректных настроек и недоверенного текста, сетевой периметр от ссылок внутри медиа, загрузчик от незавершённых и подменённых моделей. Приложение не поднимает HTTP-сервер, не принимает удалённые команды и не содержит интерфейса выполнения команд модели. Данные для смыслового поиска передаются только фиксированному `127.0.0.1:11434`, без прокси, перенаправлений и облачной авторизации.

Это проверка кода и регрессий с усилением защиты, а не доказательство отсутствия неизвестных уязвимостей. Процесс декодирования Qt Multimedia не помещён в отдельную песочницу ОС. Человек или вредоносная программа с правом записи в файлы приложения от имени пользователя могут заменить код, декодер или локальный сервис. Администратор/скомпрометированная ОС находятся вне защиты приложения. Сертификатов издателя Windows и Apple Developer ID в проекте нет: сборка macOS имеет ad-hoc подпись, Windows Authenticode не настроен.

## Изменения

| Участок | Защита в 0.2.0 | Проверка |
| --- | --- | --- |
| Открытие записи | Только локальные обычные файлы известных типов; проверяется заголовок контейнера. URL, UNC-ссылки, плейлисты и замаскированные текстовые источники отклоняются до передачи декодеру. | Поддельный MP4 с M3U, сетевые схемы, file URL с удалённым сервером, нулевые байты. |
| Медиадекодеры | Qt работает через FFmpeg с разрешённым протоколом `file`. В пакет входит только FFmpeg multimedia backend. CLI дополнительно ограничивает демультиплексоры, исключая HLS/DASH/concat. Команды передаются списком без оболочки. | Настройки runtime, реальное отклонение HLS демультиплексора, аудио- и видеоэкспорт. |
| Экспорт | Исходник не перезаписывается. Уникальный временный файл создаётся эксклюзивно. Публикация результата не заменяет уже существующий файл, включая гонку с другой программой. На Windows используется rename без перезаписи, на POSIX — link. | Проверены сохранность исходника, точность фрагмента, существующая цель, гонка и очистка временного файла. Windows-ветвь подготовлена к CI, нативно здесь не выполнена. |
| Модель распознавания | Ревизия источника и SHA-256 зафиксированы. HTTPS, проверка диапазона при продолжении, ограничение размера, проверка свободного места, hash перед принятием. Hash повторно проверяется перед ONNX-инференсом. | Повреждённый/слишком большой ответ, неверный Content-Range, отмена и продолжение без повторной загрузки, повторная проверка до ORT. |
| Одновременная загрузка | Межпроцессная блокировка QLockFile не даёт двум окнам одновременно менять `.part`. Возраст блокировки не ограничивает длительность загрузки; восстановление после падения основывается на процессе-владельце. Символические ссылки для файлов загрузки отклоняются. | Конкурентная блокировка с давним временем файла и ссылка на посторонний файл. |
| Настройки и текст | Размер JSON ограничен; проверяются структура и типы настроек/расшифровки, числовые времена, отсутствующие и повреждённые файлы. Каталог данных на POSIX закрыт режимом 0700, настройки записываются через приватный временный файл. На Windows используются права каталога LocalAppData текущего пользователя. | Повреждённые JSON, неверные типы, NaN и отрицательные времена, выход из каталога кэша. Windows ACL нативно не проверялись. |
| Отображение текста | Динамический обычный текст явно PlainText. RichText применяется только к расшифровке после экранирования HTML; строки модели не могут вставить `<img>` или разметку в интерфейс. | Проверка исходников и регрессии экранирования. |
| Смысловая модель и индекс | Локальные модели до 3 ГБ, отклонение облачных моделей; номера результатов проверяются относительно реальных фраз. NPZ загружается без pickle, проверяются размер архива и распакованных данных, форма и конечность векторов. Запрос ограничен 2000 символами. | Облачные/слишком большие модели, выдуманные ID, неверные типы и усечённые ответы, ошибки/отмена без влияния на обычный поиск. |
| Сборка | Зафиксированы версии зависимостей и build-инструментов. GitHub Actions закреплены полными SHA, токен только на чтение. В CI добавлены аудит зависимостей, статический анализ, тесты и нативная сборка на Windows/macOS/Linux. | Коммиты Actions получены через официальный GitHub API; локальная macOS сборка проверяется отдельно. CI пока не запускался: у checkout нет remote. |

## Результаты сканеров

- **pip-audit 2.10.1**: в установленном окружении сборки известных уязвимостей не найдено. Отчёт [dependency-audit.json](security/dependency-audit.json). База проверялась через сеть, не по старому локальному списку.
- **Bandit 1.9.4**: нет находок средней или высокой серьёзности. Низкие находки о `subprocess` и `os.startfile` проверены вручную: shell не используется, медиапути не формируют команды, Windows запускает установленное приложение Ollama, macOS использует `/usr/bin/open`. Подавление ошибки вывода диагностики также намеренное: отсутствие консоли в windowed-сборке не мешает доставке ошибки в UI; это покрыто регрессией. Полный отчёт [bandit.json](security/bandit.json).
- **Qt/FFmpeg**: отдельно проверены официальные рекомендации и свежий advisory CVE-2026-8461 от 11 ноября. В списке затронутых Qt указаны версии до 6.11.1 и до 6.8.8 соответствующей ветки; проект использует Qt/PySide 6.12.0. Это не означает, что все возможные дефекты декодеров исключены. Двоичные компоненты нужно проверять снова при каждом релизе.
- **55 автоматических тестов** прошли локально на macOS, включая новые негативные проверки безопасности и первый запуск с отказом сети, паузой, продолжением, пропуском Ollama и повторным запуском. Нативный Qt-сценарий проверил семь состояний онбординга в 980×660.
- **Реальная сеть модели**: догрузка последних 64 КБ GigaAM по HTTPS Range и загрузка словаря с нуля с официального зафиксированного источника завершились успешной проверкой SHA-256. Начальная часть большого файла скопирована из известной локальной модели; полный перенос всех 225 МБ по сети в этой проверке не выполнялся.

## Что ещё требуется перед распространением Windows-релиза

1. Выполнить подготовленный build/CI на Windows x64, проверить готовый EXE на чистой Windows 10 22H2/Windows 11 с обычной учётной записью: загрузку всей модели, воспроизведение, кириллические пути, отмену, экспорт и повторный запуск. macOS не заменяет этот прогон.
2. Для публичного релиза настроить подпись издателя. Неподписанная portable-сборка может вызывать предупреждения Windows; обход защит ОС не предлагается.
3. Обновлять Qt/FFmpeg/ONNX Runtime и запускать аудит на новой платформе. Python-сканер не заменяет проверку встроенных нативных библиотек.
